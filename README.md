# VPN Exit Server (Xray VLESS + REALITY)

Скрипт для развертывания выходного сервера Xray в каскадной VPN-схеме. Сервер принимает VLESS + REALITY на TCP/443, а входящие подключения разрешает только с указанного IP промежуточного (входного) сервера.

> Это именно выходной узел каскада, а не универсальный публичный VPN-сервер. Для прямого подключения клиентов правила firewall нужно менять осознанно.

## Что настраивается

- Установка Xray из официального репозитория [XTLS/Xray-install](https://github.com/XTLS/Xray-install).
- VLESS + REALITY с `xtls-rprx-vision` на TCP/443.
- Генерация UUID, пары ключей REALITY и Short ID при каждом запуске.
- UFW: входящие подключения запрещены по умолчанию; SSH открыт на TCP/22; TCP/443 доступен только с IP промежуточного сервера.
- Отключение IPv6 через отдельный файл в `/etc/sysctl.d/`.
- Запрет доступа к private IP-диапазонам на уровне Xray.
- Проверка конфигурации Xray до перезапуска службы.

## Требования

- Debian или Ubuntu с systemd.
- Доступ к серверу от имени `root`.
- Публичный IPv4 выходного сервера.
- Публичный IPv4 входного/промежуточного сервера, с которого будет приходить трафик.
- Свободный TCP/443 и доступ к GitHub для установки Xray.

## Установка

Сначала скачайте репозиторий:

```bash
git clone https://github.com/jekfev/vpn-server-setup.git
cd vpn-server-setup
```

Перед запуском укажите публичный IPv4 промежуточного сервера через переменную `MSK_IP`. Реальный адрес сервера в репозитории не хранится.

Запуск:

```bash
chmod +x install.sh
sudo MSK_IP=203.0.113.10 ./install.sh
```

В примере `203.0.113.10` — тестовый адрес из документационного диапазона. Замените его на адрес своего промежуточного сервера.

При необходимости можно изменить REALITY destination:

```bash
sudo DEST_DOMAIN=www.cloudflare.com ./install.sh
```

## Результат

После успешной установки скрипт выведет три параметра:

| Параметр | Назначение |
|---|---|
| `UUID` | Идентификатор VLESS-клиента |
| `PublicKey` | Публичный ключ REALITY |
| `ShortId` | Короткий идентификатор REALITY |

Также будет показан внешний IPv4 сервера.

Эти параметры понадобятся для настройки исходящего подключения на промежуточном сервере. Не отправляйте их в открытые чаты и не добавляйте в Git: они дают возможность использовать ваш сервер.

## Сетевые ограничения

| Направление | Правило |
|---|---|
| Входящий TCP/22 | Разрешен для SSH |
| Входящий TCP/443 | Разрешен только с `MSK_IP` |
| Остальные входящие подключения | Запрещены |
| Исходящие подключения | Разрешены |

Скрипт отключает IPv6 на уровне системы. Если на сервере нужны другие IPv6-сервисы, не запускайте его без адаптации.

## Проверка после установки

```bash
systemctl status xray
xray run -test -config /usr/local/etc/xray/config.json
ufw status numbered
ss -lntp | grep ':443'
```

Логи Xray:

```bash
journalctl -u xray -n 100 --no-pager
```

## Важные замечания

- Перед запуском проверьте IP в `MSK_IP`: при неверном значении промежуточный сервер не сможет подключиться.
- Скрипт открывает SSH только на TCP/22. Если SSH у вас работает на другом порту, добавьте соответствующее правило UFW до включения firewall.
- Повторный запуск генерирует новые UUID и ключи REALITY, а затем заменяет конфигурацию Xray. Старые клиентские параметры перестанут работать.
- Перед повторным запуском сохраните текущие параметры, если сервер уже используется.
- Скрипт рассчитан на чистый или специально подготовленный сервер. Он меняет системные настройки IPv6 и правила UFW.


## Конфигурация входного сервера Москвы

В репозитории хранится только шаблон конфигурации. Рабочий конфиг, UUID клиентов, private key REALITY, параметры подключений к выходным узлам и IP-адреса серверов в Git не добавляются.

Файлы:

- **configs/msk-config.template.json** — шаблон текущей конфигурации московского Xray.
- **configs/msk-secrets.example** — перечень локальных переменных, которые нужно заполнить.
- **scripts/render-msk-config.sh** — сборка итогового JSON из шаблона и локальных секретов.
- **.gitignore** — исключает локальные секреты и сгенерированные JSON-конфиги.

### Сборка конфига

Нужны Bash, envsubst (пакет gettext-base) и jq.

    cp configs/msk-secrets.example configs/msk-secrets
    chmod 600 configs/msk-secrets

Заполните configs/msk-secrets реальными значениями. Это shell-файл: используйте формат VARIABLE="value" и не подставляйте в него содержимое из недоверенных источников.

Затем выполните:

    chmod +x scripts/render-msk-config.sh
    ./scripts/render-msk-config.sh

По умолчанию результат будет записан в configs/msk-config.rendered.json с правами доступа 600. Этот файл исключен из Git. Скрипт проверяет наличие обязательных значений и корректность JSON, но **не устанавливает конфиг на сервер, не меняет текущий файл и не перезапускает Xray**.

Перед применением отдельно проверьте конфигурацию:

    xray run -test -config configs/msk-config.rendered.json

Не коммитьте configs/msk-secrets, сгенерированный конфиг или резервные копии с реальными данными. Перед любым обновлением рабочего конфига сделайте отдельную защищенную резервную копию и убедитесь, что тест Xray прошел успешно.
